# Melee trajectory cache reconstruction

[C] [trajectory_cache_analysis.cpp](/home/john/Desktop/cheat_re/source/reconstructed/trajectory_cache_analysis.cpp) implements the local `0x2e1ff4..0x2e20f1` fold and binds it through `InteractionCalls.trajectory_cache_definition`. Keeping the definition address preserves the native rereads after formatting. The older scalar-only callback remains a compatibility boundary.

[C] Formatting reads definition `+0x44`, `+0x34`, `+0x38`, then speed, in that order (`2e1ff4`, `2e2002`, `2e2013`, `2e2024`). Each binary32 value is promoted to double and formatted with `%f` (`2d9540..2d95cb`, format bytes at `28d32c`). Concatenation is **speed + field38 + field34 + field44**, without delimiters, followed by the signed-byte, NUL-terminated hash `2d6354`. Six fractional digits can cause different binary32 inputs to share a key.

[C] The physical mapping is **definition+34 = drag; definition+38 = gravity scale**. `2df2e8` stores incoming XMM3 at table+4 and XMM2 at table+8; `2e20cc/2e20d1` supply +34/+38 respectively. The integrator multiplies table+8 by 9.81 (`2e37c7..2e37e5`) and applies table+4 as drag (`2e3850..2e3876`). [C] This audit corrected an earlier swap in the parameter names and candidate-table inputs while preserving the actual string/hash order.

[C] `2e0e20..2e0e4c` scans exactly 1,000 hash slots at `3d8310`, stride `0x30`, including its post-first-RET matching tail. A miss rereads all three definition fields, finds the first zero hash, writes the hash and four scalar fields, constructs the candidate container and prepares 3,601 trajectories through the existing `2e3aa4` translation. No free slot returns zero. A hit returns the existing slot+8 without reinitializing it.

[I] `MovementMainState.globals` holds the copied scalar/header slots; `prediction_tables` owns candidate buffers. Native allocator addresses, string lifetimes and vector heap headers are adapted to owned C++ storage. The native vector words are not replaced with executable pointers.
