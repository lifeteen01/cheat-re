## Concrete interface

[I] Include [font_atlas_input_analysis.hpp](/home/john/Desktop/cheat_re/source/reconstructed/font_atlas_input_analysis.hpp). Raw Snapshot entrypoints are `font_config_ctor_39f550`, `font_ctor_39f3d0`, `font_atlas_add_39fd68`, `font_atlas_memory_39fe54`, `font_atlas_clear_input_3a3d04`, `font_atlas_clear_fonts_3a3c64`, `font_atlas_clear_3a3c40`, `font_ranges_unpack_3a8bec`, and `font_atlas_ranges`. The byte-value config and range getters produce the concrete data consumed by UI setup.

[I] `bind_font_atlas_input` wraps `UnityApi.external` for39f550/39fe54/3a3c40 and all eight getters. `bind_frame_font_atlas_input` installs the same adapter into a supplied `FrameDependencyApi`; unrelated effects retain their supplied implementation or remain missing. The six39fe54 arguments are atlas, owned font bytes, signed byte length, size, config bytes-or-numeric-key, and range bytes-or-numeric-key. Missing storage, typed inputs or effects stop explicitly. Existing UI setup converts reached `RendererMissing` into its documented dependency status and preserves its site.

[I] `FontAtlasInputEffects.allocate_owned` represents only genuine395158 calls. `bind_font_atlas_input_allocators` composes the released concrete `draw_core_allocate_395158` and `draw_core_free_39517c` wrappers with typed allocation/free leaves, retaining their native counter and target/user-data loads. It uses their existing flat-RVA layout. No numeric target is invoked.

[I] `marshal_owned_bytes` is a separate required storage boundary. `UnityBytes` deliberately has no native pointer, and a native stack config has no portable address. The provider copies each supplied span to an explicitly mapped numeric key. It does **not** call395158 or create an extra allocation-counter event. The adapter verifies the copied bytes and maps their initialized extent. Temporary configs may be retained in the provider's analysis pool; they have no invented native free. Font bytes with ownership1 remain available until atlas release; ownership0 sources remain available until the concrete copy finishes. Range storage remains available through the build and is not owned/freed by native config cleanup. Providers retain separate live spans and retire stale tracked bounds if a released allocation is reused at an interior key. External known Snapshot writes into tracked storage require `font_atlas_input_mark_initialized`.

[I] Call `font_atlas_input_require_font_bytes` before supplying these tracked records to the frozen builder. It checks known font bytes and bounded terminated glyph ranges, including the builder's literal default2aa2d8. This is an explicit analysis precondition. [U] It does not claim the native builder's mutation prefix when a font/range byte is indeterminate; reconstructing that symbolic parser execution remains outside this byte parser's interface. Concrete copied inputs proceed through the real parser, metrics, packing and raster code without supplied glyph results.

## Owned state and composition

[I] `FontTextStore` is authoritative for generated fonts, glyphs, advances, lookup arrays, atlas rectangles/pixels and font-list keys. Initial atlas/font records must already correspond to the supplied copied descriptors; the adapter does not silently import stale generated vectors. Input configs, scalar font fields, pixel pointers/dimensions/UVs and global range tables remain mapped Snapshot data. Allocation/free callbacks may mutate those inputs; native reloads and committed prefixes remain observable. Providers that mutate owned keys/list state must update the corresponding authoritative record as well.

[C] The end-to-end fixture supplies only synthetic copied SFNT bytes and explicit upstream UI/file roles. All15 built-in UI font requests pass through concrete config/range/ingestion adapters. The actual default builder then emits glyph metrics, UVs and raster pixels, and the new clear controller destroys the generated owned atlas. The optional file role returns an explicit native null result; no host path is opened. [C] A separate allocator composition fixture has four genuine allocation calls and three marshalling operations; its native counter is4 after ingestion and0 after the four concrete releases.
