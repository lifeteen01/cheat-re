# Literal native PE metadata acquisition

[C] `native_pe_analysis.cpp` provides separate literal bounded readers for review S1. Existing `find_export`, conventional directory helpers, `find_runtime_function`, and their current callers remain separate and retain their declared defensive behavior. [I] Consumers requiring literal acquisition should use `native_export_2ce7c8`, `native_runtime_record_2ce1f0` and `native_frame_metadata`; adding this module alone does not change the existing `audit_context_metadata` entry point.

[C] `native_header_2ce7c0` sign-extends the copied DWORD at module+`0x3c`. `native_export_2ce7c8` reads export RVA from header+`0x88`, NumberOfNames and name-array RVA, searches names forward and compares bytes exactly until mismatch or equal NUL. An unmatched name never triggers an ordinal read. Only a matching name reads the ordinal-table RVA, selected ordinal, function-table RVA and selected function RVA, then returns module+RVA. No MZ/PE/magic, NumberOfFunctions, zero-RVA, forwarder, mapped-target or directory-extent rejection is invented. Native zero on completed search miss remains distinguishable from unavailable copied bytes via the result status. [I] Finite name/string limits replace potentially unbounded malformed-input reads.

[C] `native_exception_directory_2ce1d4` reads header+`0xa0`/`0xa4` and returns module+exception RVA with unmodified raw Size. It does not require that declared extent to be copied or nonzero. `native_runtime_record_2ce1f0` consumes this exact acquisition, treats raw Size as a record count and compares the zero-extended BeginAddress with its second native argument, an RVA. It reads only the BeginAddress DWORD at each candidate; it does not reject a matching record merely because the rest of the record is unavailable. [I] Consumers of the remaining fields perform their own bounded reads. The existing overload taking a full instruction address is a separate defensive helper and is not substituted here.

[C] `native_thread_modules_2ce130` implements module/export acquisition order and output writes: `KERNEL32.DLL` base at +`0x00`, BaseThreadInitThunk numeric export at +`0x10`, `ntdll.dll` base at +`0x08`, RtlUserThreadStart numeric export at +`0x18`. Each write precedes the next lookup; earlier writes survive a later unavailable effect. [U] Module lookup is an explicit typed OS effect over supplied owned module snapshots. A supplied zero base is not turned into an invented successful module or rejected by a special null rule; subsequent required reads must be available.

[I] `native_frame_metadata` joins literal export and raw exception acquisition to the existing `analyze_sample_unwind_2ce3dc`. It retains the parser's output accumulator, including rejected-register output, and exposes the conventional unwind summary separately. Missing native unchecked-entry dereferences become explicit unavailability. This function constructs detection evidence only, with no runnable context, gadget selection, stack synthesis or numeric-address execution.

[I] Completion fields describe different stages: a complete `NativePeStatus` can contain an incomplete unwind traversal, and `SampleUnwindResult::complete` can accompany `rejected_rsp_encoding`, zero return and retained output. The older `audit_context_metadata` still uses defensive acquisition before invoking the literal parser. `describe_executor_3cdbd4` returns a fixed event summary and performs no executable operation.
