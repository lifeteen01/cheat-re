# 04 — Entity enumeration, ESP and culling

[C] The sample enumerates client-resident entities, classifies them, builds cheat-owned collections and uses those collections to draw world/player information. [I] Withholding hidden entities' state at replication time is materially different from merely preventing their rendering. [U] Static cheat code alone cannot establish the server's current replication policy, exact PVS boundaries or what a particular session actually received.

## Enumeration and draw flow

[C] `Client.LateUpdate` (`0x2f8574`) calls classifier `0x31acd0` at `0x2f85e5`, overlay `0x3098a4` at `0x2f8d40`, and world/entity draw loop `0x2fb72c` at `0x2f8d4d`. [C] The classifier receives cheat collection root `0x2187d0`. Evidence: [frame flow](/home/john/Desktop/cheat_re/dump_analysis/semantic_reconstruction/02_rendering/2f8574.asm).

[C] `0x2f8034` obtains a collection through a hard-coded GameAssembly-rooted pointer chain: `GameAssembly+0xf0ee490`, then object/static storage including `+0xb8`, `+0x18` and `+0x20`. [C] The accessor also calls nested helpers `0x2f9950`/`0x2f996c`: these transform each 32-bit half of a stored value through `0x2f8540`/`0x314b80`, then use resolver `0x315bd0`. The resolver checks an 8 KiB block tag, slot bound and allocation bitmap before reading a direct qword or complemented dword entry (`0x315bd0–0x315c33`). [I] This is an encoded-reference/handle indirection; the original runtime type name is unresolved [U]. [C] `0x31acd0` calls that accessor at `0x31ad88`, gets backing array/count using `0x316504` (`+0x10`) and `0x316524` (`+0x18`), and reads entries at array `+0x20 + index*8` (`0x31adbb–0x31ae1a`). [I] This is a client network-entity collection. [U] The source-level name `BaseNetworkable.clientEntities` is plausible but is not confirmed by a referenced string or matching metadata; do not treat that field name as recovered. Evidence: [collection accessor](/home/john/Desktop/cheat_re/dump_analysis/semantic_reconstruction/04_esp/2f8034.asm), [classifier](/home/john/Desktop/cheat_re/dump_analysis/semantic_reconstruction/04_esp/31acd0.asm).

[C] Classification combines runtime type-name/hash comparisons, prefab-name tests, a player category/tag comparison against `6` (`0x31faf7–0x31fb0e`), local-player exclusion, state filters, maximum distance and friend/enemy configuration. [C] Selected player/NPC entries are appended through `0x3177b4` (`0x31faf2`, `0x31fdf1`); that helper stores the entity pointer and an extra category byte in a cheat-owned record. [I] The cached collections separate world objects and player-like targets for subsequent drawing/targeting. Evidence: [player filter excerpt](/home/john/Desktop/cheat_re/dump_analysis/semantic_reconstruction/04_esp/31fa70_31fe10.asm), [record insertion](/home/john/Desktop/cheat_re/dump_analysis/semantic_reconstruction/04_esp/3177b4.asm).

## Server-side culling / PVS implications

[I] To remove hidden information from this ESP's inputs, the server must avoid replicating current hidden entity existence/location/state and sensitive attributes to an unauthorized observer, rather than send them and rely on client render culling. Relevant inputs are the enumerated entity collection, player/model state, held item/name/identifier data and transforms described above (`0x31acd0`, `0x3098a4`, `0x2fb72c`). [I] Visibility/interest decisions should account for legitimate gameplay needs and authorized team/party data separately.

[I] The implemented readers demonstrate what the cheat **expects to find in client memory** when present: positions, types/prefabs, player flags, names, held items and skeletal transforms. [U] They do not prove that every remote player, every bone, all container contents or all hidden world entities are always transmitted. Some data can be derived locally from known prefab/model assets; dynamic bone transforms need not each be network fields.

[I] Previously received positions and locally saved stash/SAM locations can persist after replication stops. Effective culling needs sensible entity retirement/invalidation and consideration of what can be inferred from old state; it cannot erase an observer's prior knowledge. Evidence for retention capability: “Successfully saved stash” (`0x2fd003`) and “Successfully saved sam” (`0x31f1bb`). [U] This report does not establish cache lifetimes or enumerate all stale-state behavior.
