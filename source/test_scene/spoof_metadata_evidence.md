# Owned spoof metadata evidence and limits

The scene remains ordinary-call/metadata-only. A separate executable, freestanding
executor now exists in [source/freestanding](/home/john/Desktop/cheat_re/source/freestanding/README.md).
Its owned context tests and no-import DLL do not complete the native scanner or
integrate spoofcall into this scene/base.

[C] This evidence concerns static bytes in owned `Snapshot` objects. The test scene does not link `03_stack_spoof_spoofcall.cpp` or invoke a spoof-call executor. See the [integration audit](/home/john/Desktop/cheat_re/dump_analysis/semantic_reconstruction/test_scene/fidelity/integration_review.md) for the scene's separate lifecycle limits.

| Interface | What its result establishes |
|---|---|
| `audit_context_metadata` / `reconstruct_context_evidence` | [C] Defensive export and exception-directory acquisition followed by the literal sample unwind parser. Acquisition validates PE signatures/magic/extents, rejects null/forwarded/uncopied export targets, and requires full runtime records. This entire acquisition pipeline is not a literal native translation. |
| `native_export_2ce7c8` / `native_runtime_record_2ce1f0` / `native_frame_metadata` | [C] Separate literal bounded acquisition: no added export target or directory-extent validation; exact BeginAddress comparison; raw directory Size used as record count. The record finder reads only BeginAddress; the frame consumer separately needs the rest of the record. |
| `analyze_sample_unwind_2ce3dc` | [C] Literal metadata arithmetic/traversal, including nonstandard operand selection, per-chain accumulator reset, and register-4 rejection. [I] Missing bytes, cycle detection and a 64-entry depth bound are analysis safeguards. |
| `summarize_unwind` | [I] Separate conventional allocation summary, with a wider total and explicit unsupported cases; it is not the sample parser or a Windows unwinder. |
| `describe_executor_3cdbd4` | [C] Eight fixed event descriptions, independent of the supplied evidence. No target validation, argument marshalling, stack mutation, return rewriting, continuation selection, restore simulation or call occurs. |

[C] `SampleUnwindResult::complete` reports modeled traversal completion. Register-4 rejection can complete with return value zero while preserving earlier output. The old audit maps that output into its evidence and supplies a rejection limitation. The literal frame API exposes `rejected_rsp_encoding` separately. Likewise, a complete `NativePeStatus` from `native_frame_metadata` can coexist with incomplete nested unwind results; PE acquisition and unwind traversal have distinct completion fields. None denotes an executable context or successful call.

[C] Existing [hook checks](/home/john/Desktop/cheat_re/source/reconstructed/hooks_checks.cpp) cover exact versus containing runtime lookup, raw Size over-traversal, return-versus-output divergence, allocation operand selection, save-register reset, padded chain lookup and cycle detection. Added regressions cover truncated headers/opcodes/allocation operands/skipped slots/chain RVAs, unavailable chained headers, acyclic depth exhaustion, all three register-4 rejection branches, and 32-bit accumulation wrap versus the conventional wider total. DWORD additions and the normal return load are visible at `2ce4ab`, `2ce4e3`, `2ce4f9` and `2ce54b` in the [static parser excerpt](/home/john/Desktop/cheat_re/dump_analysis/semantic_reconstruction/03_stack/2ce3dc.asm).

[C] Existing [native PE checks](/home/john/Desktop/cheat_re/source/reconstructed/native_pe_checks.cpp) cover malformed signatures, signed negative headers, unchecked ordinal/target values, unavailable matching ordinals, bounded lookups, partial module acquisition and explicit embedded-module bases. Added comparisons start with an otherwise-valid PE accepted by the defensive reader, then isolate null/forwarded/uncopied targets, incomplete export/exception extents, inaccessible unmatched ordinals, a copied BeginAddress with missing remaining fields, and successful PE acquisition with truncated unwind data. Defensive optional results do not distinguish a miss from unavailable metadata; the literal result status does.
