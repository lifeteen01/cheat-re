### Limiter semantics

[C] `0x3226b0` maintains separate accumulated vertical and horizontal movement at `0x3e6090`/`0x3e6094`, uses ground/contact-related tests and a time-dependent allowance, and returns false when either budget is exceeded (`0x3228b4–0x3229ad`). [I] This approximates fly/movement validation. [U] Exact server algorithm equivalence and unobfuscated parameter names are not established.

[C] The concrete translation in [05_server_observable.cpp](/home/john/Desktop/cheat_re/source/reconstructed/05_server_observable.cpp) preserves the following details of `0x3226b0..0x3229ad`: its timer decrements before the player-validity early return; a previously grounded state saves the old position as an anchor; the physics path tests the midpoint lowered by `2`, then a midpoint query with tolerance `0.01`, then a capsule from midpoint minus `1.5` vertically to midpoint plus `1.3`, with radius `0.4`, mask `0x59a12101` and final argument `1`. [C] Positive capsule contact prevents airborne accumulation. Query bit `8`, a positive first query, or predicate `0x36a364` also take reset paths. [U] These are numeric arguments and branch roles, not recovered game method/type names.

[C] On the airborne path, nonnegative vertical displacement is accumulated; horizontal distance is accumulated only when it exceeds absolute vertical displacement. If neither changes a budget, no budget comparison runs. With an expired timer the limits are `0.4 + 1.5 = 1.9` vertically and `1.5 + 5 = 6.5` horizontally; with a positive timer they are `5 + 1.5 = 6.5` and `10 + 5 = 15`. Strictly exceeding a limit returns false **before** storing either proposed accumulator. Equality passes. [C] Ground/contact paths reset both accumulators. [U] These are this DLL's local estimates, not authoritative server thresholds.

[C] `0x32dbb0` estimates permitted movement using player state and elapsed time, adjusts measured displacement, maintains accumulator `0x3f212c`, clamps it, compares it to its allowance, and exposes a display value at `0x3e6098` (`0x32dcf1–0x32dea3`). It reads active `AutoAdjustSpeed` at `0x32dcde`. [I] This is a speed-budget limiter. Evidence: [both helper bodies](/home/john/Desktop/cheat_re/dump_analysis/semantic_reconstruction/05_server/violation_helpers.asm).

[C] The translated speed path validates its player/related-object inputs **before** decrementing its timer, maps four state-query results to three float arguments, and overrides those arguments to `(1,0,0)` under the observed state/config gates (`0x32dc54..0x32dcff`). Permitted distance is the supplied result of `0x36a3a8` multiplied by elapsed time. Measured distance uses only X/Z displacement. When measured distance exceeds permitted distance, the `0x32cdcc`/`0x32cc74` boundary supplies a vector/context result; the code subtracts `max(0, horizontal_dot) * 10 * elapsed`, then clamps the measured distance at zero. [C] This vector is not normalized in the observed path. [U] Its game meaning remains unresolved and is not replaced by an invented slope/terrain model.

[C] The speed allowance is `2` with an expired timer and `10` with a positive timer; its clamp extent is the allowance plus `2`. The routine clamps the accumulator to that signed extent, subtracts permitted distance and clamps again, then compares against the allowance. It adds measured displacement only if the first comparison permits it, clamps again, and compares a second time (`0x32de12..0x32de91`). Equality rejects, and both rejection paths retain the accumulator stores already performed. The display scalar is updated only if the final accumulator is at most `2`. [C] The C++ helpers preserve scalar SSE source selection and ordered/unordered branch behavior for quiet-NaN inputs; an unordered accumulator passes the carry-based comparison and suppresses the display store. [U] Signaling-NaN exceptions, payload propagation, and exact game floating-library/environment equivalence are unverified.

[C] `replay_tick_limiters_32cea8` translates the limiter/correction tail at `0x32d9ca..0x32db1e` over owned input/state records. Both validators run before exemption/config tests. Movement correction is enabled by `(AntiViolations && option[0]) || byte[0x3d8241] || byte[0x3ef4e1]`; speed correction requires `AntiViolations && option[3]`. Each failed, nonexempt check separately restores the old position and conditionally invokes the supplied `0x32a9f8` correction callback with its observed true argument. [I] Earlier position-list/teleport work and exemption computations are explicit inputs to this tail. [C] The older decision projection also now matches `MINSS elapsed,1` at `0x32cfcd`, including its selection of `1` for NaN elapsed time.

[I] Server-side checks should recompute budgets from authoritative state and retain a history of attempted movement, corrections, action timestamps and accumulated budget pressure. Merely counting large rejected moves may miss clients that repeatedly stop at an estimated boundary. [U] “AntiFly”, “AntiSpeed”, “AntiNoclip” and “AntiTerrain” menu names do not prove four fully implemented independent validators; the traced hook directly demonstrates the above helper/correction paths.

## Projectile prediction

[C] `0x2e2474` and `0x2e3734` load `9.81f` from RVA `0x28db18` and `0.03125f` (`1/32`) from `0x28dadc`. [C] `0x2e2474` advances position by a velocity-step vector, subtracts gravity from the vertical velocity, and stores 320 samples (`0x2e24f5–0x2e2593`). It then searches candidate trajectory results through helpers including `0x2e3074` and `0x2e38e4`. [I] This is trajectory generation plus trajectory/angle search, not a standalone packet generator.

[C] `0x2e3734` builds an initial 2D velocity from an angle and speed, integrates position, applies gravity and a drag term each step, writes 320 horizontal/vertical samples, tracks maximum horizontal travel, and records a first index meeting a minimum-time/distance condition (`0x2e37c7–0x2e38c5`). [I] The 320-step horizon is ten simulated seconds; it is not evidence of a 32 Hz network send cadence. Evidence: [first predictor](/home/john/Desktop/cheat_re/dump_analysis/semantic_reconstruction/05_server/2e2474.asm), [second predictor](/home/john/Desktop/cheat_re/dump_analysis/semantic_reconstruction/05_server/2e3734.asm).

[C] The missing search is now implemented as concrete offline C++: `candidate_angle_2e3e94` maps index `i` to `(i * pi) / 3600 - pi/2`; `build_candidate_tables_2e3aa4` builds the observed 3,601 tables using `0x2e3734`. Constants were read directly from DLL RVAs `0x28db00`, `0x28db08`, `0x28db10`. [C] The scorer `0x2e3074..0x2e3284` prunes the candidate's horizontal sample range with lower/upper binary searches when maximum travel is at least `10`, includes adjacent segments, and projects a reference sample onto each 2D segment. The reference sample index is `max(segment_index - first_qualifying_step, 0)`. Segment squared length at most `0.000001` uses projection fraction zero; otherwise the fraction is clamped to `[0,1]`. It retains the first strictly better squared miss and segment index. Evidence: [search/scorer/angle byte excerpts](/home/john/Desktop/cheat_re/dump_analysis/semantic_reconstruction/05_server/search_helpers.asm), [binary-search continuations and comparator bytes](/home/john/Desktop/cheat_re/dump_analysis/semantic_reconstruction/05_server/search_bounds.asm).

[C] `search_candidates_2e2474` implements the outer stride `candidate_count / 70` (`51` for 3,601 tables), the strict local-rise test, refinement calls, and the final-tail fallback at `0x2e25b8..0x2e26b1`. `refine_candidates_2e38e4` narrows the interval in thirds, scans once its width is at most five, and qualifies only a **squared** miss strictly below `0.02` (`0x2e38e4..0x2e3a4b`). Winning supplied endpoints retain segment index zero; they are not silently rescored. [I] Extra statuses bound empty, zero-stride and invalid-boundary copied inputs; these are analysis safeguards, not recovered return values. The observed builder supplies the full 3,601-table case.

[C] `predict_2e2474` also translates the selected-output path `0x2e26b7..0x2e281f`: lead steps are `max(segment - first_qualifying_step + 1, 0)`, motion is cleared only when both `0x2f824c` and `instanthit` are true, the relative position plus the scaled motion is projected horizontally, the selected angle supplies vertical/horizontal components, and the final vector is normalized by direct division. [U] The `0x2f824c` result is supplied as an input. `std::sin` and `std::cos` represent unresolved game math-library calls without a bit-identical claim. [C] Magnitudes now use the literal inverse-root/Newton/reciprocal helper `0x2e3c88`, including its tiny positive result for zero; see [math reconstruction](/home/john/Desktop/cheat_re/source/reconstructed/math_reconstruction.md). [C] The usual wrapper `0x2e2374` passes reference gravity scale zero (`0x2e23dd..0x2e23ed`); the generic predictor preserves the observed byte-valued scale input.

[C] The existing `0x2e3734` integration and negative-X fallback were checked against their byte excerpts. `0x2e33c0` uses a `0x7fffffff` mask to select magnitude/sign; `copysign(speed, vertical_velocity)` expresses that result. Qualification uses ordered greater-or-equal comparisons after `COMISS/JB`, while maximum travel uses ordered strict greater after `COMISS/JBE`, so quiet NaNs do not qualify or replace the maximum. [U] No original instruction is executed by this verification.

[I] Prediction alone changes local aim selection, not necessarily the network format. Its output can bias firing direction toward a future target position; a server may observe unusually accurate lead/drop compensation. Detection should combine aim/target-motion statistics with validated launch velocity, gravity, drag and legitimate weapon parameters. [U] Precision alone is not proof of cheating and the numeric timestep is not an exclusive fingerprint.
