# Game update offset inventory

[C] This export contains **141 distinct numeric fixed inputs** in its verified scope: **64 GameAssembly-relative addresses** and **77 recovered game-field start values**. [U] This is not a proven complete upper bound for the cheat. Remaining unclassified literal ownerships are excluded from the total, rather than asserted to be game offsets.

[C] [manual_update_offsets.txt](/home/john/Desktop/cheat_re/source/offset_inventory/manual_update_offsets.txt) is the requested numbers-only list: one hexadecimal value per line, sorted and deduplicated. [C] Separate numbers-only files are [GameAssembly RVAs](/home/john/Desktop/cheat_re/source/offset_inventory/gameassembly_offsets.txt) and [game-field starts](/home/john/Desktop/cheat_re/source/offset_inventory/game_field_offsets.txt). [C] [manual_update_offsets.csv](/home/john/Desktop/cheat_re/source/offset_inventory/manual_update_offsets.csv) distinguishes modules from member offsets and retains receiver contexts, native sites, source locations and confidence.

[I] These are fixed inputs to validate against a matching game build; a patch does not necessarily change every value. Lazy caching of a hardcoded address does not automatically discover a replacement. A resolver fed by a hardcoded root still depends on that root; its derived output is excluded.

[C] [auto_resolved_excluded.csv](/home/john/Desktop/cheat_re/source/offset_inventory/auto_resolved_excluded.csv) records name-based methods, named exports, signature results, module bases, derived vector components and other exclusions. **None contributes to the total.** Cheat configuration/state/cache RVAs, generic managed/metadata headers and non-offset identifiers are excluded. [U] Resolver names/patterns and non-offset decode/ID constants may independently need maintenance; this inventory does not claim they survive every update.

[C] Numeric offsets shared by multiple receiver types occur once in the text file. [U] That does not make the underlying fields the same: two classes using `+0x20` may move differently. Use the CSV context when updating a layout. Receiver/source-member names are inferred [I] unless independently established; fixed accesses are recorded with their source evidence [C].

[C] Module references were traced from the established GameAssembly base global `0x3d6f00` through the supplied native instruction listing, including the second range bound in `0x3306e2`. Decisive instruction encodings were checked against preserved DLL bytes. The field list covers the audited getter catalogue, explicit receiver roles in the enumerated recovered controllers and reviewed additional field starts. [U] It does not classify every remaining numeric displacement in the image or substitute for matching game metadata.

[U] [unclassified_not_counted.csv](/home/john/Desktop/cheat_re/source/offset_inventory/unclassified_not_counted.csv) retains 982 other literal values with unresolved ownership; many can be cheat/UI/library fields. These values are **not** included and are **not** a valid upper bound on all possible runtime-derived game dependencies.

[C] [summary.json](/home/john/Desktop/cheat_re/source/offset_inventory/summary.json) records counts, exclusions, scope and exact hashes of the read inputs. [C] The reproducible exporter is [export_offsets.py](/home/john/Desktop/cheat_re/dump_analysis/offset_inventory_sidechat/export_offsets.py), and exact output hashes are in [OUTPUTS.sha256](/home/john/Desktop/cheat_re/dump_analysis/offset_inventory_sidechat/OUTPUTS.sha256). This side-chat export writes only its own new inventory paths; it does not alter the active reconstruction, its build or generated progress/index files. No sample instruction is executed and no endpoint is contacted.
