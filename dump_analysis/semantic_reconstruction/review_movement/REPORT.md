## Confirmed issues and precise corrections

[C] **M1 — movement/launch cache constructors swapped drag and gravity.** Native `2df2e8` saves incoming xmm3 in xmm7 (`2df305`) and incoming xmm2 in xmm8 (`2df308`), then writes xmm7 at table+4 (`2df329`) and xmm8 at table+8 (`2df333`). Native `2e3734` uses +8 for gravity (`2e37c7`) and +4 for drag (`2e3850`); the same offsets recur in `329e8c/329ecf` and `32a552/32a575`. `2dfe64` forwards these argument registers unchanged to the constructor.

[C] At `32567d`, projectile+38 goes into xmm13, while `325683` puts projectile+34 in xmm14. `325815` forwards xmm14 as xmm3 and `325820` forwards xmm13 as xmm2. Therefore projectile+34 is drag and projectile+38 is gravity. Similarly `318404` reloads ammo+34 into xmm3 and `31840d` reloads ammo+38 into xmm2 immediately before the launch constructor. The reviewed C++ called `create_table(speed,+38,+34,fourth)` and assigned these opposite roles.

[C] Corrected both field names and constructor mapping to table+4=+34 drag/table+8=+38 gravity, while retaining the distinct format order **speed,+34,+38,fourth**. Launch constructor fields now reload after formatting at their native sites. The fourth launch **constructor** value remains zero; the fourth **format** double remains explicit caller-supplied copied input. Regression fixtures use unequal 0.25/1.5 values and verify both copied table offsets, typed parameters and exact format/hash order. Independently reverting either movement or launch argument mapping makes the corresponding fixture fail.

[C] **M2 — grenade solver returned final integrated velocity instead of selected initial velocity.** In `317194`, `317500/317509/317517/31750d` copy the current trial's initial velocity from rsp+30/+38 into rbp+94/+9c. `31751f/317526` then save the record from rbp+90 to rbp+40; initial velocity occupies rbp+44..4c. The return at `317628/31762d/317620/317655` copies these initial velocity bytes to output+10/+18. The flight solver's integrated velocity is a separate field, not the aiming vector returned there.

[C] The reviewed implementation retained only `best.velocity` after gravity/drag updates and returned that as `out.direction`. Corrected it to retain the initial velocity of each selected best trial. A nonzero two-segment grenade flight now preserves initial zero Y aim even though the simulated velocity has accumulated gravity. The fixture additionally requires positive selected flight time to prevent a zero-flight false positive. Reverting only this selected-velocity assignment causes the new fixture to fail.

[C] **M3 — both low-velocity MINSS caps used 1.0 instead of 1.495.** Exact preserved DWORD at `28daf8` is `0x3fbf5c29` (1.495f). `3254d5` caps the previous scale using this address and `3257a1` caps each trial's scale using the same address. Reviewed C++ supplied 1.0f for both. Corrected both caps to the exact bit literal. With base speed40 and first trialscale1.5, native candidate speed is float bits `0x426f3333`, formatting `59.80`; the committed chosen scale remains1.5. The fixture verifies those speed bits and the format-derived pool hash. Reverting the cap to1.0 makes the regression fail. The previous-scale product is a native dead local in this caller, but its literal calculation is preserved too.

[I] These findings are about the supplied reconstruction's semantics on owned inputs. They do not establish live feature success or operational sample behavior.
