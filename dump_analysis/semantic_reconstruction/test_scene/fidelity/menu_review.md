## Prioritized findings

### 1. P1 — The original page graph and main-menu entry path are replaced

[C] Native registration sites `35fc98..35fdcd` register 21 page thunks across category indices 0–6; `35fe00..35fea9` initially visits pages to populate registration/search state. `388b4c` is only a dispatcher: `388bfb` obtains the selected page slot and `388c00` indirectly calls its target. See [main-menu controller](/home/john/Desktop/cheat_re/source/reconstructed/frame_dependencies_main_menu.cpp:513) and the exact [21 thunk/body ranges](/home/john/Desktop/cheat_re/source/reconstructed/menu_pages_specs.inc:1).

[C] The scene instead creates one `Owned ESP` category pointing at invented key `410100` ([menu.cpp:95](/home/john/Desktop/cheat_re/source/test_scene/menu.cpp:95)); its page callback accepts only that key and calls authored `render_page()` ([menu.cpp:247](/home/john/Desktop/cheat_re/source/test_scene/menu.cpp:247)). It never binds `bind_menu_pages`, `bind_menu_controls_frame`, or the actual `replay_frame_menu_35d5ac`/`frame_main_menu_35fc8b` path. Calling `388b4c` therefore does **not** exercise any original registered page body. The three checkbox keys, distance range/format, labels, and page layout are host choices.

[I] This is the principal scope gap: original category/subtab transitions, search, Favorites, configuration queues, localization, combo/multiselect/int-slider/keybind/tooltip branches and page-conditioned controls remain absent from this executed scene, even where recovered implementations exist elsewhere. **Regression:** compose the real menu/page/control bindings; assert each original thunk reaches its registered body and preserves ordered control requests/config keys; exercise category/subtab changes, search filtering/Favorites, representative conditional controls and queued configuration operations. Keep external game results as explicit owned inputs.

### 2. P1 — The displayed hex editor cannot receive text or editing keys

[C] Picker `379a27` really calls editor `3c0538`. Native `3c1223..3c12a1` reads/consumes the UTF-16 queue at `context+37c0`; the recovered [process controller](/home/john/Desktop/cheat_re/source/reconstructed/imgui_text_input_process.cpp:154) also consumes modifiers, shortcuts, navigation, Backspace/Delete, Enter and Escape. The scene [Input contract](/home/john/Desktop/cheat_re/source/test_scene/scene.hpp:14) has no text/key/modifier input. [Menu frame setup](/home/john/Desktop/cheat_re/source/test_scene/menu.cpp:364) never stages that queue or key transitions. [Win32 dispatch](/home/john/Desktop/cheat_re/source/test_scene/host.cpp:314) has no `WM_CHAR` or `WM_KEYUP` path; arrow keys and A/D change the background scene, and Escape destroys the window regardless of editor focus.

[I] Editor entry counts prove rendering/controller entry, not usable hex editing. **Regression:** focus `color_hex`, enter/select/replace text using the real host event route, verify resulting RGB and ESP vertex colors, exercise Backspace/arrows/Enter/Escape, and assert editing consumes scene shortcuts. Preserve the evidenced picker quirk: parsed fourth hex channel is not assigned to alpha (`379aaa..379af6`; [picker:78](/home/john/Desktop/cheat_re/source/reconstructed/menu_color_picker_analysis.cpp:78)). A test expecting hex alpha replacement would encode a false oracle.

### 3. P2 — Mouse bookkeeping disables recovered editor selection behaviors

[C] Native `3c112d/3c113e` checks mouse delta at `context+f8/fc` before held-drag selection; `3c0fd8/3c1002` uses click count at `+3752` for multi-click selection. The scene never writes those deltas and unconditionally writes both click-count fields `+3752/+375c` to 1 every visible frame ([menu.cpp:365](/home/john/Desktop/cheat_re/source/test_scene/menu.cpp:365)). Zero-initialized Snapshot storage leaves the deltas zero.

[I] A text-editor drag cannot reach its motion-selection branch, and double/triple-click selection is unreachable. **Regression:** track actual previous/current mouse positions and click timing/counts, then verify drag selection across several frames and double/triple-click selections through the scene, not by directly seeding editor state. Include release outside, hide/minimize/resize and focus-loss cases; the existing slider cancellation checks do not establish editor selection/deactivation fidelity.

### 4. P1 — Window/popup behavior is bypassed rather than integrated

[C] Original main UI begins through `35fefe -> 38cfa4`, uses header/navbar/main/subtabs/content child windows and closes through `390994`. Its recovered width is `(126*navbar_animation + 850)*scale`, height `580*scale` ([controller:549](/home/john/Desktop/cheat_re/source/reconstructed/frame_dependencies_main_menu.cpp:549)). The scene manually seeds a window/context, resets coordinates, and clips a fixed 340×444 panel each frame ([menu.cpp:331](/home/john/Desktop/cheat_re/source/test_scene/menu.cpp:331)). Supplying `bind_imgui_window_details` to the editor is not executing the original Begin/End/child lifecycle, focus stack, scroll/resize/position and popup ordering.

[C] Native color preview `386438` toggles an animated popup; `3868be` begins it, `38691e/38692b` updates focus/display order, `386932..38694e` handles outside-click closing, and `386959` calls the picker. The scene calls `379680` directly and always embeds it ([menu.cpp:298](/home/john/Desktop/cheat_re/source/test_scene/menu.cpp:298)). It also omits checkbox color/key/description child paths evidenced at `3bda14/3bdc16/3bddb9` ([checkbox:121](/home/john/Desktop/cheat_re/source/reconstructed/menu_controls_checkbox.cpp:121)).

[I] **Regression:** exercise actual Begin/End and child bindings with balanced current-window/focus/clip stacks; open color through preview `386438`, edit it, close by outside click, check animation/focus/z-order and cursor restoration. Check content access in a small viewport via the recovered applicable scroll behavior. Authored viewport clipping alone does not establish these behaviors.

### 5. P1 for original appearance/lifecycle — Font setup is substituted

[C] Original setup `35ccf4` clears the atlas (`35cd46 -> 3a3c40`), configures recovered style/colors, requests 12 family/size combinations plus three defaults from embedded data, and attempts a Chinese font/range path ([setup:132](/home/john/Desktop/cheat_re/source/reconstructed/frame_dependencies_ui_setup.cpp:132)). The scene supplies 95 authored 5×7 ASCII glyphs in one 128×128 atlas ([resources:149](/home/john/Desktop/cheat_re/source/test_scene/resources.cpp:149)), aliases every supplied bucket/size to one font ([menu:166](/home/john/Desktop/cheat_re/source/test_scene/menu.cpp:166)), and hand-seeds its palette/style. Its link manifest excludes the atlas-input/default-builder modules.

[I] Text draw/lookup correctness with those glyphs cannot establish original font metrics, icon/language coverage, wrapping, alignment or theme fidelity. **Regression:** feed locally recovered font bytes/config/ranges through `setup_frame_ui_35ccf4`, ingestion and the actual builder; verify font-family/size selection, representative Latin/icon/non-ASCII glyph metrics and geometry, then clear/rebuild/release with allocation/lifetime checks. [U] Platform font availability, exact original initialized atlas, native allocator behavior and language-font push/pop behavior in the full frame remain unverified.
