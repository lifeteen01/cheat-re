## P1 — S1: `37bc98` hard-codes 16 where the original reads mutable `0x248ed0`

[C] In [original label assembly](/home/john/Desktop/cheat_re/dump_analysis/semantic_reconstruction/world_esp/37bc98.asm), **RVA 0x37bda7** loads the line/measurement size from **global 0x248ed0**. The special Indicator0/2/3 plus family2 path selects10 at **0x37bd93**; ordinary DisplayName follows the global load. The value is used for font scale at **0x37bdc8/0x37bdd4**, measurement at **0x37be01/0x37be21**, and side-counter spacing at **0x37bebb**. Above-name placement subtracts the measured width/2 and measured height at **0x37bf8d–0x37bfdc**. This is a data dependency, not a literal16 in the original helper.

[C] [Current label implementation](/home/john/Desktop/cheat_re/source/reconstructed/world_esp_player_labels.cpp:57) instead uses `const float line = small ? 10.0f : 16.0f`. [WorldLabelFonts](/home/john/Desktop/cheat_re/source/reconstructed/world_esp_analysis.hpp:620) has current-font and font records but no shared `0x248ed0` size. [Renderer binding](/home/john/Desktop/cheat_re/source/reconstructed/renderer_helpers_world.cpp:10) refreshes font pointer/nominal size before each label, but does not read this global. [Measurement binding](/home/john/Desktop/cheat_re/source/reconstructed/font_frame_bindings.cpp:86) faithfully uses the supplied request size, so it preserves the wrong16 rather than correcting it.

[C] The current [ESP text consumer](/home/john/Desktop/cheat_re/source/test_scene/esp.cpp:333) now synchronously executes `font_text_plain_361bcc` for each of the six label commands, including empty slots. Original [361bcc assembly](/home/john/Desktop/cheat_re/dump_analysis/semantic_reconstruction/font_text/361bcc.fresh.asm) applies family0 size10 at **0x361cff–0x361d0b** and writes that size to **0x248ed0 at 0x361d30**. The [reconstructed controller](/home/john/Desktop/cheat_re/source/reconstructed/font_text_controllers.cpp:32) does the same. The [worker](/home/john/Desktop/cheat_re/source/reconstructed/world_esp_player_worker.cpp:270) invokes the six label helpers sequentially; original sequential calls are visible at **0x312e7f, 0x312ebe, 0x312efd** and following sites in [overlay assembly](/home/john/Desktop/cheat_re/dump_analysis/semantic_reconstruction/world_esp/3098a4.txt:7900).

[I] Consequently, after the first family0 text-controller call, subsequent ordinary labels must measure/place using shared size10. This applies to Birch/Cedar in the same frame and, after persistence, Aster in subsequent frames. The current code keeps measuring them at16. Restoring the original text controller corrected rendering passes but exposed this missing cross-call state dependency. Empty label slots matter because they still run the controller and write the shared size.

[C] A read-only byte check of [the recovered mapped image](/home/john/Desktop/cheat_re/dump_analysis/unpacked/cheat.unpacked.dll) found **0x248ed0 initially16.0** and **0x28db1c=10.0**. The scene's [constructor](/home/john/Desktop/cheat_re/source/test_scene/esp.cpp:124) seeds `context+0x3c30=16`, which is a different cell; its zero-initialized Snapshot does not explicitly seed `0x248ed0`. [I] A faithful owned composition needs an explicit initial value for this shared state and must preserve/read subsequent controller writes. Replacing the hard-coded16 with a hard-coded10 would still lose the original dependency and cold-state behavior.

[C] The effect is concrete with the existing authored metrics: [resources.cpp](/home/john/Desktop/cheat_re/source/test_scene/resources.cpp:160) uses nominal14 and advance8 for every character of `Birch`; [renderer_measure_3a3874](/home/john/Desktop/cheat_re/source/reconstructed/renderer_helpers_font.cpp:151) scales advances by requested-size/nominal. Binary32 arithmetic gives width **45.7142868 at16**, versus **28.5714302 at10**. With the existing top-side placement and spacing4, the current logical origin is approximately **8.57143 pixels farther left and6 pixels higher** than a size10 measurement would place it, before glyph-coordinate flooring. This is derived from owned metrics and the native placement formula; it is not a comparison to unavailable assets.

[C] [ESP evidence](/home/john/Desktop/cheat_re/source/test_scene/esp_evidence.md) currently says “Label placement measures at size16 separately.” That accurately describes the implementation, but original `0x37bda7` does not establish a permanent separate16-pixel layout rule. [I] Update that explanation with the implementation correction.

[I] **Locally fixable change:** represent the copied `0x248ed0` value in the label dependency state and refresh it from the authoritative Snapshot before each label, after preceding synchronous output effects. Supply an explicit initial size in owned fixtures. Use this value for ordinary measurement, font scale and side spacing, retaining the indicator override and existing nominal-size restoration. Preserve the actual `361bcc` writes rather than deriving the size from a disconnected constant/configuration copy.

[I] **Targeted regression:** start the shared size at16, invoke DisplayName and the real synchronous text consumer with family0, require the first measurement16 and output size10, then require the next label measurement10. Verify the next entity and next frame also measure10, including empty intermediate slots. Separately start at13 or22 to prove the state is read rather than another literal. Assert actual per-entity logical positions relative to projected top midpoints and, where practical, final glyph positions. The negative control should change only the ordinary layout size back to16 and fail.
