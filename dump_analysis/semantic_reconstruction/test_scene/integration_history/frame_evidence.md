# Owned frame-controller adapter

[C] `FrameLifecycle::frame` in [frame.cpp](/home/john/Desktop/cheat_re/source/test_scene/frame.cpp) calls the existing `replay_unity_frame_2f8574` controller on every positive-viewport invocation. This changes actual callback execution order, rather than rearranging trace entries. The adapter never converts an evidence address to a callable pointer, reads live game memory, installs a hook, or executes copied sample instructions.

[I] This adapter is an owned fixture composition. A completed `UnityResult` means the recovered controller finished against its supplied typed boundaries. `UnityResult::submitted` means its `execute_unity_commands_3b2004` path reached the owned recording sink. It does **not** mean Unity rendered anything. `FrameReport::gpu_executed` remains false. No numerical fidelity percentage follows from this work.

## Explicit warm fixtures and unexecuted boundaries

[I] Construction still seeds eight nonzero owned bundle keys, `ui_initialized`, `configs_loaded`, backend cache tokens, camera/mesh/rect/material/property/command-buffer/texture tokens, and vertex descriptors. Backend cache `flags=3` and original **context bit 2 only** / `context_detected=true` are declared ordinary-call dispatcher readiness fixtures. The original target bit 1 starts clear and is populated by the recovered frame from the actual copied Client record. These readiness fixtures do not establish native context detection or an executor. Numeric keys are never cast to function pointers.

[C] `owned_client.cpp` supplies one owned assembly/image/class/method/type database. Callback readers validate requested keys and read copied class/method names, pointer fields, parameter count and return type; lookup misses return zero, and a deliberately absent metadata callback stops the actual initializer. `bootstrap_signatures_334bf4` really visits the assembly/class/method, strips `System.Void` to `Void`, computes the `Client::LateUpdate(): Void` signature and caches the MethodInfo. `initialize_client_362118` stores the supplied owned module key, assigns the historical strings as data, and invokes `install_method_info_copy`. The latter saves the old MethodInfo qword and replaces only bounded owned bytes with the numeric reconstructed detour key. The constructor consumes that record rather than a separate arbitrary saved-original constant. `FrameReport::client_install` retains the actual result, record, signature method, old/new words and string values. No historical filesystem path is opened.

[C] Failed class/method selection has a complete initializer result with `installed=false`; the frame explicitly rejects it at `3621f2`. Missing metadata/module returns the original failure prefix before frame setup. A zero old method word remains a successful copied installation, then the recovered frame rejects its zero original at `2f87a4`. Repeat initialization preserves the first saved original instead of capturing the replacement. Opaque record bytes at `+18..+27` remain unchanged.

[U] Cold bundle loading, cold UI/backend resource creation, config path lookup/loading, actual IL2CPP/ICall resolution, pinning, native shader/font/texture creation and initial splash activation remain unexecuted. Copied Client metadata selection/installation and original-target acquisition now execute; they do not establish matching game metadata or native hooking. Setup-three (including the separate fourteen-hook `315c34` body), entity/container refresh, timed classification, gate side effects, four game workers, backbuffer work, remaining world root, raids and inventory remain typed deferred records. [I] Render-target descriptors are authored owned keys encoded into a local byte record; orthographic matrices use local algebra from controller-supplied arguments. Mesh-native readiness is a supplied owned object mapping, not a live mesh probe. [C] Recognized boundary arguments are checked for exact `UnityValue` alternatives and arity. An optional `accept_effect` consumer can reject a boundary; the recovered controller stops with `missing_dependency` and preceding records/writes remain. The record exists even when its consumer refused it, so consumers must inspect `FrameReport::result` rather than count records as completed native work.
